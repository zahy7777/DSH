# tiny-dsh
- 给 DSH 造一个基座框架
- DSH 是万物皆插件（331 个包），所以需要一块基座，让一堆互不相识的插件在一个进程里共存、互相使用能力、能独立装卸
- 做两件事，按顺序
	- 搓基座框架
	- 在它上面搓 DSH 极简模式
- 服务于：优雅、极简、Linus 工程美感、概念
- 这是作者自己的东西
- Cordis / DSH 是参考材料，不是权威
- 这个文件只放指令。词汇表、已否决的形状、栽过的坑、进度、参考坐标都在 [README.md](README.md)

# 文档格式
- `#` 是大块，`##` 是具体的某条规则，`###` 很少用
- `-` 是内容，缩进用 tab
- 井号永远在行首，不缩进，不挂在某个 `-` 底下
- 标题和它的列表紧挨着，块与块之间空一行
- 每一行都以 `#` 或 `-` 开头
- 不用加粗、不用引用块、不用表格
- 反引号只标标识符
- 代码块缩进在 `-` 下面，块内逐字保留

# 唯一的铁律
- 推演先行
- 从需求出发，一步步"因为…所以…"，直到推出形状
- 推演没完成，不准写代码
- 这条靠什么管用
	- 想违反，就得伪造一条推演链
	- 伪造比不做更费劲，于是你会停下来问，这东西到底谁需要
	- 不靠禁止，靠让违规的成本变高

## 代码只映射推演，不能新增
- 判据：写每个对外接口前问，它在推演链的哪一步被逼出来的
- 答不出就停下补推演

## 命名在推演阶段定
- 判据：推出一样东西就当场定名
- 定名要探讨四样：它是什么、为什么这个词、还有哪些候选、各有什么坑

## 一次只加一个
- 判据：它必须是「上一环不够用了」逼出来的
- 不许提前引入后面的概念

## 以闭环为单位
- 判据：每环是一段能跑、能验证的代码，跑不起来的不算完成
- 每个闭环交付七样：推演、概念与命名、内部数据结构、对外接口、代码、验证、参考坐标

## 参考以推演为准
- 判据：结论和 Cordis / DSH 不同时，用推演，并在注释里写明差异

## 做完停下等审
- 判据：每环写完停下，等作者确认再进下一环

## 推荐代替提问
- 判据：技术选型直接给推荐加理由加对比，不逐条征求同意

# 命名
- 概念在代码里只以名字存在
- 名字错了，心智模型就歪，而歪掉之后后面每一行代码都在加固那个歪
- 名字要说清是什么，说清在哪一层，说清干什么

## 不许发明黑话，必须用业界高权术语
- 定名之前先做一轮对照：这件事在业界叫什么
- 找三个以上框架在同一位置上的命名，看交集
- 每个候选都要写清好处和坑
- 判据：说得出这个词在哪个框架或哪篇论文里被人多年使用吗
- 说不出就换
- 我在对话里临时打比方用的说法不算命名，不许进代码，不许进文档的命名位
- 栽过：我把这件事叫过"能问的地方"，把一次加载叫过"开户口"，都是我编的

## 声明式优先于命令式
- 判据：念出方法名
- 能直接说"它干了什么"就好
- 得先想"它怎么做"就改名

## 一词一义，不同层次不同名
- 判据：同一个标识符在同类或同模块里只有一个含义
- 要 `serviceName` 和 `pluginName`，不要两个 `name`

## 注释是失败的信号
- 想写注释解释代码时，先去改代码
- 只允许留三类：为什么、契约、参考坐标
- 判据（含量）：注释行数除以总行数小于 20%
- 判据（性质）：每条留下的注释都要能说出属于上面三类里的哪一类，说不出就删

# 结构
- 读者工作记忆只有 4±1 个槽位
- 判断任何代码只问一句：读懂并安全地改它，需要在脑子里同时挂着几个东西

## 不声明没人用的东西
- 判据：`grep`
- 没人读的字段、没人调的方法、没人传的参数，删

## 链上每步都要携带信息
- 判据：把中间某一层去掉，信息丢了吗
- 没丢就是噪音

## 能单向就不双向
- 判据：删掉一半，另一半还能跑吗
- 不能就是有环，有环就是读者不能局部理解

## 调用链尽量短
- 判据：每一步都问，这层是必要的，还是我为了方便加的

## 结构必须显式
- 禁止使用构造函数参数属性，类的字段必须在类体中逐项声明
- 构造函数只接收参数并逐项完成必要赋值，不把字段声明藏进参数列表
- 禁止用隐式继承、隐式初始化或语法糖隐藏概念关系

## 代码必须最小
- 只保留职责和契约要求的语句，能删掉的中间变量、分支和包装全部删掉
- 不得重复执行同一个清理、注册或通知动作
- 不能用幂等性掩盖重复调用；发现重复就删除多余调用

# 目录
- 结构如下
	```text
	src/               只有源码
	  kernel/          kernel：不能是插件的那部分
	  dsh/             DSH 的插件（还没开始）
	tmp/fixture/       素材：被测试和被演示依赖的固定物
	tmp/test/          脚本：把 fixture 跑起来、打印结果
	tmp/tsconfig.json  检查 fixture/ 和 test/
	```
- 源码和测试严格分开，测试绝不混进 `src/`
- 顶层目录对应完整概念，不按技术角色分类
- 注释用 `// ══ 大节 ══` 和 `// ── 小节 ──` 分区

# 工具链
- 跑用 `tsx`，查用 `tsc`，可以使用 `const enum`，禁止使用构造函数参数属性
- `src/` 和 `tmp/` 的类型检查都必须零错误
