# 本仓库约定（给后来的 Agent）

这是一个**学习文档仓库**，不是代码项目。没有 `package.json`，不装依赖，不提交 `node_modules`。

## 这是什么

面向「熟 Python / Java、零 JavaScript 基础」的读者，用**心智概念先行 + 线性推进**的方式讲 TypeScript。

## 三条硬约束

1. **线性。** 每节只引入一个核心心智概念。正文里不许出现还没讲过的术语；如果确实需要，先用一句话把它定义清楚，并注明"详见第 X 节"。
2. **不凭空出现。** 每节开头的"为什么需要它"必须从上一节已建立的概念推出来。推导不出来，说明这节的顺序错了，应该调整 [README.md](README.md) 的地图。
3. **事实必须实测。** 文档里出现的每一条输出、每一条报错原文，都必须在本机真跑过再写。禁止写"应该输出"。

## 文档骨架（每节必须遵守）

```
# NN · 概念名

## 心智锚点        —— 一句话
## 为什么需要它     —— 从上一节推出来
## 核心概念        —— 正文
## Python / Java 对照 —— 三栏表格
## 实测            —— 可跑的代码 + 真实输出
## 坑清单
## 回收钩子        —— 这节被后面哪节用到
```

## 写作风格

- 正文、注释、说明一律用中文。技术术语保留英文原词（`prototype`、`closure`、`narrowing`）。
- 对照 Python / Java 时，只讲**语义差异**，不堆语法糖清单。
- 允许并鼓励"劝退式"提醒：直接指出哪条路是错的、为什么错。
- 不写废话式的总结段落。高信息密度优先。
- 反直觉的点要单独标出来，这些才是真正花时间的部分。

## 输出格式（Obsidian）

读者用 **Obsidian** 阅读，因此：

- **只产出 Markdown。** 仓库里不出现 `.ts` / `.js` / `package.json`，代码一律写在文档的围栏代码块里。
- 每篇文档开头带 YAML frontmatter，`tags` 用 `卷N/卷名` 形式（如 `卷一/JS执行模型`），这样 Obsidian 的标签树能按卷分组。
- 交叉引用用**标准 Markdown 相对链接**，不用 `[[wikilink]]`——标准链接在 Obsidian 和 GitHub 上都能跳。
- 结论性内容用 Obsidian callout，GitHub 也渲染同一套语法：
  - `## 心智锚点` 的正文 → `> [!important]`
  - `## 坑清单` → `> [!warning]`
  - 会贯穿全课的硬事实 → `> [!danger]`
- 文件名不含空格，链接里就不需要 `<...>` 转义。

### 「事实必须实测」怎么在不产出 `.ts` 的前提下执行

验证在**系统临时目录**里做，仓库里不留任何产物：

```bash
cd "$(mktemp -d)" && npm i typescript   # 跑完即弃
```

文档里贴的输出，必须是那个临时目录里**真实打印出来的原文**。

## 追加式写作（重要）

**已经写完的文档一律冻结，不再修改。** 追问、补充、纠正一律写成**新文件**——因为读者不会回头重读旧文档，**改旧文档等于没写**。

命名规则：节号后加一个小写字母，再跟概念名和「追问」：

```
01-值与类型.md          ← 原始讲授，冻结
01a-值与类型追问.md     ← 第 1 节的第一次追问
01b-值与类型追问.md     ← 第二次，依此类推
```

- 字母后缀让文件名按名称排序时自然排在原文件之后。
- **追问文件必须自包含。** 读者不会翻回原文，所以不能写「如前面所述」「见上文」，要能把上下文重新交代清楚。
- 追问文件的结构可以比正式章节松散（按「追问一 / 追问二」组织即可），但**「事实必须实测」照旧**。
- `README.md` 是索引、不是讲授内容，是这条规则的**唯一例外**：每新增一个文件都要在对应卷里挂一行，否则新文件会变成孤儿。
- 如果追问推翻了原文，**不改原文**，在新文件里明确写「原文哪里错了、正确的是什么」。

## Obsidian 本地配置

`.obsidian/` 已加入 `.gitignore` 并停止跟踪（文件仍在磁盘上）。里面是 Obsidian 的本地状态，`workspace.json` 每动一下窗口就会变，提交它只会让之后每次 commit 都带噪音。

要同步 vault 配置的话，单独把 `appearance.json` / `core-plugins.json` 这类加回来，**不要加 `workspace.json`**。

## 目录

顶层按"卷"划分，每卷内部按概念顺序编号：

```
ts-learning/
├─ README.md          课程地图 + 进度（唯一进度来源）
├─ AGENTS.md
├─ 01-js-runtime/     卷一 · JS 执行模型
├─ 02-ts-types/       卷二 · TS 类型系统
├─ 03-ts-compiler/    卷三 · TS 编译器内核
└─ 04-node-toolchain/ 卷四 · Node 工程框架
```

文件名格式：`NN-概念名.md`（追问文件为 `NNa-概念名追问.md`），编号即阅读顺序。

## 维护流程

1. 写完一节，回到 [README.md](README.md) 把该行状态改成 ✅，并更新底部「进度」计数。
2. 用 `git commit` 提交，message 说明新增了哪一节。
3. 如果一节写下来发现顺序不对，**改地图而不是打补丁**——调整 README 的编号，重排，保持线性。

## 已知环境事实

- Node v25.7.0：能直接 `node x.ts`（strip-only，只擦类型不做检查）。
- strip-only 模式**拒绝** `enum`、`namespace`、构造函数参数属性，报 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。需要时加 `--experimental-transform-types`。
- 本机没有全局 `tsc`，需要类型检查时用 `npx typescript@latest`（实测可用版本：7.0.2）。
- TS 7 的坑：当前目录存在 `tsconfig.json` 时，命令行直接指定文件会报 `TS5112`。要么加 `--ignoreConfig`，要么在干净目录里跑。
