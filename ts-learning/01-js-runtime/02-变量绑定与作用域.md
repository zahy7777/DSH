# 02 · 变量绑定与作用域

## 心智锚点

> [!important] 这一节要装进脑子的东西
> `let` / `const` / `var` **不是三种写法，是三种绑定规则。** 它们的区别不在「能不能改」，而在两件事：**绑定的作用域边界**（函数还是块）和**绑定什么时候才生效**（提升 / TDZ）。

---

## 为什么需要它

第 1 节把「值」分成了两类——原始值和对象。但值得先有名字才能用。

```js
let b = a;
```

这行到底发生了什么？它**创建了一个叫 `b` 的绑定**，然后把它指向 `a` 那个值。注意"绑定"这个词：**变量不是一个装东西的盒子，而是"名字 → 值"的一条关系。**

这个概念一立住，`const` 的真相立刻清楚：**它锁的是这条关系，不是那个值。** 后面会看到这条推论有多反直觉。

`let` / `const` / `var` 就是三套不同的绑定规则。它们在两个维度上不同：

1. **作用域边界**：绑定活到哪结束
2. **生效时机**：绑定从哪一刻起可以被访问

---

## 核心概念

### 1. 三条规则的完整差异

| | `var` | `let` | `const` |
|---|---|---|---|
| 作用域边界 | **函数** | **块** | **块** |
| 提升后初值 | `undefined` | 未初始化（TDZ） | 未初始化（TDZ） |
| 声明前访问 | 得到 `undefined`，**不报错** | `ReferenceError` | `ReferenceError` |
| 重复声明同名 | 允许 | `SyntaxError` | `SyntaxError` |
| 必须初始化 | 否 | 否 | **是** |

**这张表就是本节的全部内容。** 下面逐条拆开。

> [!tip] 实际怎么选
> **默认 `const`，需要重新赋值才降级成 `let`，永远不用 `var`。**
> `var` 是 1995 年的设计遗产，它存在的唯一理由是要兼容 1995 年的网页。

### 2. 作用域边界：`var` 是函数级，`let`/`const` 是块级

「块」指 `{}` 包起来的一段——`if`、`for`、`while` 的花括号都算。

```js
function f() {
  if (true) { var v = "var"; let l = "let"; const c = "const"; }
  console.log(v);   // "var"   —— 漏出块了
  console.log(l);   // ReferenceError
  console.log(c);   // ReferenceError
}
```

真实输出：

```
var  漏出块: var
let  没漏出: ReferenceError
const 没漏出: ReferenceError
```

循环上更明显：

```js
for (var i = 0; i < 3; i++) {}
console.log(i);   // 3   —— 循环变量漏到外面了
for (let j = 0; j < 3; j++) {}
console.log(j);   // ReferenceError
```

真实输出：

```
var 漏出循环: 3
let 没漏出循环: ReferenceError
```

> [!important] 语言锚点：`var` ≈ Python，`let` ≈ Java
> - **Python 没有块作用域。** `if True: y = 1` 之后 `y` 在外面照样能访问。所以 Python 人对 `var` 会觉得很自然，对 `let` 反而要重新适应。
> - **Java 有块作用域。** 所以 Java 人本来就在用 `let` 的语义，只是换成 `var` 会莫名漏水。
> - 实测 Python：`if True: y = 1` 之后 `print(y)` → `1`；`for i in range(3)` 之后 `print(i)` → `2`。

### 3. `const` 锁的是绑定，不是对象

这是本节第一个反直觉点，也是从「绑定」这个概念直接推出来的。

`const` 禁止的是**把 `arr` 这个名字重新指向别的东西**，它**不管**那个东西自己怎么变：

```js
const arr = [1];
arr.push(2);          // 完全合法
console.log(arr);     // [1, 2]

const obj = { n: 1 };
obj.n = 2;            // 完全合法
console.log(obj.n);   // 2

const x = 1;
x = 2;                // TypeError: Assignment to constant variable.
```

真实输出：

```
const 数组可以改内容: [ 1, 2 ]
const 对象可以改属性: 2
const 重新赋值 -> TypeError: Assignment to constant variable.
```

**这个行为与 Java 的 `final` 完全一致**——`final` 引用不能再指向别的对象，但对象内容随便改。Python 没有对应物（它是靠"全大写命名"这个约定）。

### 4. TDZ：`let` 也提升，只是提升后「未初始化」

这是本节第二个反直觉点，而且它是**可推理出来的**，不是要背的规则。

先看现象：

```js
console.log(tdz);   // ReferenceError: Cannot access 'tdz' before initialization
let tdz = 1;
```

那 `let` 到底提升不提升？用一个对照实验就能验出来——`typeof` 对**完全不存在**的变量是安全的：

```js
typeof neverDeclared     // "undefined"，不报错
typeof tdz2              // ReferenceError！
let tdz2 = 1;
```

真实输出：

```
先访问后声明 -> ReferenceError: Cannot access 'tdz' before initialization
未声明变量的 typeof: undefined
TDZ 里 typeof 也抛 -> ReferenceError
```

**推理**：如果 `let` 完全不提升，那 `tdz2` 就跟 `neverDeclared` 一样"不存在"，`typeof tdz2` 应该同样安全地返回 `"undefined"`。它却抛了 `ReferenceError`——说明**引擎知道这个绑定存在**，只是它还没被初始化。

所以准确的说法是：

> `let` / `const` **也提升**，但提升之后处于"已声明、未初始化"的状态。从作用域开始到初始化语句执行之间，这段区间叫 **TDZ（Temporal Dead Zone，暂时性死区）**。访问 TDZ 里的绑定一律 `ReferenceError`。

**TDZ 是在帮你。** 它把「先用后声明」这个 bug 立刻炸出来，而不是像 `var` 那样悄悄给你一个 `undefined` 让 bug 往下游跑。

### 5. 提升：`var` 的静默 bug

`var` 的声明被提到函数（或全局）顶部，但**赋值留在原地**：

```js
console.log(v);   // undefined —— 不报错！
var v = 1;
console.log(v);   // 1
```

真实输出：

```
var 提升后是: undefined
赋值后: 1
```

注意这行的可怕之处：**它不报错，只是给你 `undefined`。** 一个拼错的名字、一个顺序颠倒的初始化，都可能在几百行之外才爆。这就是「永远别用 `var`」的真正理由。

### 6. 遮蔽（shadowing）：内层可以盖住外层

作用域是可以嵌套的。规则很简单：**内层能看见外层，外层看不见内层；同名时内层盖住外层。**

```js
const x = "outer";
{
  const x = "inner";
  console.log(x);   // inner
}
console.log(x);     // outer
```

真实输出：

```
块内: inner
块外: outer
```

**注意这是两层不同的绑定，只是重名。** 内层的 `x` 是个全新的绑定，跟外层毫无关系（这跟重新赋值是两回事）。

### 7. 一个真会害人的坑：不声明就赋值

```js
undeclared = 1;   // 没有 let/const/var
```

- 在**非严格模式**（普通 `.js` 脚本）下：**静默创建一个全局变量**，一切正常
- 在**严格模式**（ESM 模块、`class` 内部、`"use strict"`）下：`ReferenceError: undeclared is not defined`

真实输出：

```
sloppy 允许: 1
strict -> ReferenceError: undeclared is not defined
```

**这就是为什么现代 JS 代码一律写成 ESM 模块**（`.mjs` / `"type": "module"`）——模块自动是严格模式，这类静默错误立刻变成显式报错。卷一第 8 节讲模块时会展开。

## Python / Java 对照

| | JS `var` | JS `let` / `const` | Python | Java |
|---|---|---|---|---|
| 作用域边界 | 函数 | 块 | **函数** | 块 |
| 需要声明吗 | 是 | 是 | **不需要**（赋值即绑定） | 是 |
| 先使用后声明 | `undefined`，静默 | `ReferenceError`（TDZ） | `NameError` / `UnboundLocalError` | 编译错误 |
| 重复声明同一名字 | 允许 | `SyntaxError` | 允许（直接覆盖） | 不允许 |
| 常量 | 无 | `const`（只锁绑定） | 无（靠全大写约定） | `final`（只锁引用） |

> [!note] Python 其实也有「TDZ」
> 在函数体里，只要出现过 `x = 1`，Python 就把 `x` 判定为**局部变量**——于是函数开头访问它就会炸：
> ```
> UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
> ```
> 本质上和 JS 的 TDZ 是同一件事：**绑定存在，但还没有值。** 区别是 Python 的这个判定只发生在函数级作用域（因为 Python 没有块作用域）。

实测少量重复声明的行为：

```js
let a = 1; let a = 2;   // SyntaxError: Identifier 'a' has already been declared
var b = 1; var b = 2;   // 合法
const c;                // SyntaxError: Missing initializer in const declaration
var e;                  // 合法，e 是 undefined
let d = 1; var d = 2;   // SyntaxError: Identifier 'd' has already been declared
```

## 坑清单

> [!warning] 九条
> 1. **`const` 不冻结对象内容** —— 只锁绑定。要真冻结用 `Object.freeze()`。
> 2. **`const` 必须初始化** —— `const c;` 是 `SyntaxError`。
> 3. **`var` 会漏出块和循环** —— 这就是「永远不用 `var`」的理由。
> 4. **`var` 的"先使用"不报错** —— 给你 `undefined`，bug 跑到下游才爆。
> 5. **`let` 也提升** —— 别以为它能免疫提升，它是"提升了但不给你用"。
> 6. **TDZ 里连 `typeof` 都抛错** —— 这跟"完全没声明的变量"行为不同。
> 7. **内层同名是新建绑定，不是赋值** —— 遮蔽 ≠ 修改外层。
> 8. **不声明就赋值在非严格模式下静默建全局变量** —— 别写出这种代码，用 ESM。
> 9. **`let` 与 `var` 不能同时声明同名** —— 混用会直接 `SyntaxError`。

---

## 回收钩子

- **「变量是绑定，不是盒子」** → 第 3 节「函数与闭包」：**闭包捕获的是绑定，不是值。** 这一条直接解释了循环里 `var` 和 `let` 那个经典差异。
- **块作用域与遮蔽** → 第 3 节：函数作用域是更大的一层块。
- **严格模式** → 第 8 节「模块」：ESM 自动严格，这是它相对脚本的一大优势。
- **`const` 锁绑定不锁内容** → 卷二：TS 有 `readonly` 修饰符，它管的才是"内容能不能改"，跟 `const` 是两件事。
