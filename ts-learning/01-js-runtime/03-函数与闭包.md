# 03 · 函数与闭包

## 心智锚点

> [!important] 这一节要装进脑子的东西
> **闭包 = 函数 + 它出生时的词法环境。**
> 函数不只是「一段代码」，它随身带着自己**定义位置**处的那些变量绑定。而且——**它捕获的是绑定本身，不是当时的值。**

---

## 为什么需要它

第 2 节留下了一个钩子：

```js
for (var i = 0; i < 3; i++) { ... }
for (let j = 0; j < 3; j++) { ... }
```

这两个循环的变量在「作用域边界」上不同，但那只解释了一半。真正的问题在第 2 节里没法回答：

> **如果循环体里放的是函数，它们各自记住的是哪个 `i`？**

回答这个问题需要「闭包」这个概念。它是 JS 最核心的机制，也是异步、回调、模块私有变量、React Hook 这些东西的地基。**不真正理解闭包，后面全是玄学。**

---

## 核心概念

### 1. 函数是一等值

在 JS 里，函数跟数字、字符串一样是**值**——可以赋给变量、当参数传、当返回值、存进对象。

```js
function twice(f, x) { return f(f(x)); }
const inc = n => n + 1;

console.log(twice(inc, 1));           // 3
const table = { up: inc, down: n => n - 1 };
console.log(table.up(1), table.down(1));  // 2 0
```

真实输出：

```
当参数传: 3
当返回值: function
当属性存: 2 0
```

Java 人要注意：Java 的方法**不是值**，你得先包成「函数式接口」再传。Python 的函数本来就是一等值，这一点两者一致。

### 2. 函数声明 vs 函数表达式：提升行为不同

```js
function decl() { return 2; }        // 函数声明
var expr = function () { return 1; }; // 函数表达式
```

- **函数声明**：整个函数被提升，**声明之前就能调用**
- **函数表达式**：只有 `var` 被提升（函数本体没有），所以声明前调用报 `TypeError`

```js
expr();              // TypeError: expr is not a function
var expr = function () { return 1; };
decl();              // 2   —— 完全正常
function decl() { return 2; }
```

真实输出：

```
表达式早调用 -> TypeError: expr is not a function
声明早调用: 2
```

注意报错类型是 **`TypeError` 而不是 `ReferenceError`**——这正是第 2 节的推论：`var expr` 被提升了，所以 `expr` **存在**，只是此刻它的值是 `undefined`。调用 `undefined` 当然是 `TypeError`。

> [!tip] 报了 `TypeError: xxx is not a function`
> 九成是两种情况之一：调用了一个值是 `undefined` 的东西，或者拼错了名字（拼错也走 `var` 提升那条路）。**先去确认那个变量此刻是什么值**，别急着怀疑函数定义。

### 3. 闭包：环境活过外层函数

看这个：

```js
function counter() {
  let n = 0;
  return () => ++n;
}
const c1 = counter();
const c2 = counter();
console.log(c1(), c1(), c1());   // 1 2 3
console.log(c2());               // 1
```

真实输出：

```
c1 三次: 1 2 3
c2 独立: 1
```

`counter()` 早就返回了，它的局部变量 `n` 按常理应该销毁。可是 `c1` 每次调用还能让 `n` 递增——**`n` 活着**。

**这就是闭包：函数把它出生位置的环境一起带走了。**

两个要点：

- **`c1` 和 `c2` 各自持有独立的环境。** 每次调用 `counter()` 都会创建一套全新的绑定，所以 `c2` 从 1 重新开始。
- **Python 的闭包行为完全一样**（Python 要用 `nonlocal` 才能改外层变量，JS 不需要）：

  ```
  Python: c1 三次: 1 2 3
  Python: c2 独立: 1
  ```

### 4. 核心：闭包捕获的是「绑定」，不是「值」

这是本节最重要的一条，也是唯一必须真正理解、不能背的一条。

```js
function make() {
  let v = "初始";
  const get = () => v;    // get 捕获的是绑定 v，不是此刻的值 "初始"
  v = "改过了";            // 事后修改 v
  return get;
}
console.log(make()());    // "改过了"
```

真实输出：

```
捕获后可再变: 改过了
```

**如果闭包捕获的是"值"，这里应该输出「初始」。** 它输出「改过了」——因为 `get` 记住的是**那个叫 `v` 的绑定本身**，后面谁改它，闭包就看到新值。

> [!danger] 这一条解释了一整类 bug
> 闭包看到的是**变量**，不是**快照**。
> 所以「循环里创建函数」这种写法，只要那些函数共享同一个绑定，它们最后**全都看到循环结束时的那个值**。

### 5. 回收第 2 节的钩子：`var` 与 `let` 的循环差异

现在可以回答第 2 节那个问题了。

```js
const withVar = [];
for (var i = 0; i < 3; i++) { withVar.push(function () { return i; }); }
console.log(withVar.map(f => f()));    // [3, 3, 3]

const withLet = [];
for (let j = 0; j < 3; j++) { withLet.push(function () { return j; }); }
console.log(withLet.map(f => f()));    // [0, 1, 2]
```

真实输出：

```
var 循环: [ 3, 3, 3 ]
let 循环: [ 0, 1, 2 ]
```

**为什么？** 用「捕获绑定」这一条就能推出来，不需要额外记忆：

- **`var i` 是函数级的，整个循环只有「一个」绑定 `i`。** 三个函数捕获的是**同一个** `i`。循环结束时 `i` 是 3，所以三个都返回 3。
- **`let j` 是块级的，`for` 循环每轮迭代创建一个「全新的」绑定。** 三个函数各自捕获了属于自己的那个 `j`，所以是 `0 1 2`。

> [!note] `let` 在循环里的这个行为是语言规范专门规定的
> `for (let ...)` 每轮迭代都会复制一份新的绑定，这是为了让你能自然地写闭包。它不是"块作用域的副作用"，是**刻意的设计**。

### 6. Python 有完全相同的陷阱

这不是 JS 的怪癖，Python 一模一样——`[lambda: i for i in range(3)]` 里的三个 lambda 共享同一个 `i`：

```
Python lambda 陷阱: [2, 2, 2]
```

（Python 是 `2`，JS 是 `3`，因为 `range(3)` 结束后 `i` 停在 `2`，而 JS 的 `for` 会先自增再判断。）

**Java 反而没有这个问题**——Java 的 lambda 只允许捕获 `final` 或"事实上 final"的局部变量。你根本写不出捕获可变循环变量的代码，编译器直接拦住。这是 Java 少有的、比 JS/Python 更安全的地方。

---

## Python / Java 对照

| | JS | Python | Java |
|---|---|---|---|
| 函数是一等值 | ✅ | ✅ | ❌ 方法不是值，要包成函数式接口 |
| 闭包存在 | ✅ | ✅ | ✅（lambda / 内部类） |
| 闭包捕获什么 | **绑定** | **绑定** | **值**（且必须 effectively final） |
| 改外层局部变量 | 直接改 | 需要 `nonlocal` | **不允许** |
| 循环里创建闭包 | `var` 全错 / `let` 正确 | 全错（经典陷阱） | 写不出来（编译拦截） |

## 坑清单

> [!warning] 七条
> 1. **闭包捕获绑定不是值** —— 想固定某个值，得在外层先用一个新变量接住它。
> 2. **循环里创建函数，`var` 必错** —— 一律用 `let`。
> 3. **函数表达式不会整体提升** —— 声明前调用报 `TypeError` 而不是 `ReferenceError`。
> 4. **`TypeError: xxx is not a function`** 通常意味着那个变量此刻是 `undefined`。
> 5. **每次调用外层函数都会创建新环境** —— 闭包之间不会互相污染，这是特性不是 bug。
> 6. **闭包会让被捕获的变量无法释放** —— 长生命周期闭包别捕获大对象。
> 7. **箭头函数和普通函数有区别** —— 主要在 `this` 上，那是第 5 节的事，这里先记住"有区别"。

---

## 回收钩子

- **闭包捕获绑定** → 第 6 节「事件循环」与第 7 节「Promise / async」：**所有回调都是闭包**，异步代码里"为什么我拿到的是更新后的值"全靠这一条解释。
- **函数是一等值** → 第 6 节：回调能被"稍后调用"的前提，就是函数能当参数传出去。
- **`this` 的区别** → 第 5 节「`this` 绑定」：箭头函数不绑定自己的 `this`，普通函数绑定，这是它俩最本质的差异。
- **每次调用创建新环境** → 卷二：TS 的泛型也遵循「每次调用独立实例化」的思路，可以类比。
