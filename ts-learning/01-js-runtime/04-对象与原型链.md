# 04 · 对象与原型链

## 心智锚点

> [!important] 这一节要装进脑子的东西
> **JS 没有「类」，只有「对象 + 一条指向另一个对象的链」。**
> 属性查找就是沿着这条链往上走，一直走到 `null` 为止。第 01a 篇说的「`instanceof` 查的不是类型表，是原型链」，指的就是这条链。

---

## 为什么需要它

到第 3 节为止，你已经有了：**值**（第 1 节）、**名字绑定**（第 2 节）、**函数与闭包**（第 3 节）。

但还有一个东西没解释。第 01a 篇里留下了一句结论：

> `d instanceof Dog` 的动作是：从 `d` 出发沿原型链往上走，看有没有碰到 `Dog.prototype`。

**当时没解释「原型链」是什么。** 这一节把它拆开。

而且这是 Java 人最需要换掉心智模型的地方：**Java 的对象方法来自它的类；JS 的对象方法来自另一个对象。** 差异很大。

---

## 核心概念

### 1. 对象是「属性的集合」

一个字面量对象就是一堆键值对，没有任何魔法：

```js
const animal = { speak() { return "..."; }, kind: "动物" };
```

**注意 `speak` 只是一个值为函数的属性。** JS 里没有"方法"这个特殊的成员种类——方法就是"值恰好是函数的属性"。

### 2. 每个对象有一个隐藏链接，指向「它的原型」

这个链接在语言里通过 `Object.getPrototypeOf()` 读写，习惯上记为 `[[Prototype]]`。

用它来"继承"：

```js
const animal = { speak() { return "..."; }, kind: "动物" };
const dog = Object.create(animal);   // 造一个对象，把它的原型设为 animal
dog.name = "旺财";
```

现在 `dog` 自己只有一个属性 `name`，但它照样能访问 `kind` 和 `speak()`：

```
自己的属性: 旺财
从原型链拿到: 动物 / ...
```

### 3. 属性查找：先自己，再沿链往上，直到 `null`

**这就是全部规则。** 访问 `dog.kind` 时引擎做的事：

1. `dog` 自己有 `kind` 吗？没有。
2. 沿着 `[[Prototype]]` 到 `animal`。有吗？有 → 返回 `"动物"`。

链的终点是 `null`——`null` 上当然没有属性，所以查找结束，返回 `undefined`。实测：

```js
Object.getPrototypeOf(dog) === animal            // true
Object.getPrototypeOf(animal) === Object.prototype // true
Object.getPrototypeOf(Object.prototype) === null   // true
```

真实输出：

```
链的终点: null
链: dog -> animal -> Object.prototype -> null: true true true
```

**`Object.prototype` 是所有普通对象的链尾**，它自己再往上就是 `null`。

> [!tip] Python 人其实早就懂这个
> Python 的属性查找也是沿链走的：`实例 → 它的类 → 基类（按 MRO）`。
> **结构上跟 JS 的原型链是同构的。** 区别只有一点：Python 链上挂的是**类**，JS 链上挂的是**普通对象**。Java 人反而要重新学——Java 的方法解析是编译期按类层次定死的。

### 4. 遮蔽（shadowing）：自己的属性盖住链上的同名属性

```js
const base = { v: "原型上的" };
const child = Object.create(base);
child.v = "自己的";
console.log(child.v);   // "自己的" —— 自己有了，就不再往上找
delete child.v;
console.log(child.v);   // "原型上的" —— 删掉自己的，链上的又露出来
```

真实输出：

```
遮蔽后: 自己的
'v' in child        : true
child.hasOwnProperty: true
删掉自己的之后: 原型上的 | hasOwn: false
```

**「自己有没有」和「能不能访问到」是两件事**，这两个操作符的回答不同：

| 问题 | 写法 | 包含原型链？ |
|---|---|---|
| 能不能访问到 `v`？ | `"v" in child` | ✅ 包含 |
| 自己身上有 `v` 吗？ | `Object.hasOwn(child, "v")` | ❌ 只看自己 |

（老代码里你会看到 `child.hasOwnProperty("v")`，现在推荐 `Object.hasOwn`。）

### 5. `class` 是语法糖

ES2015 引入的 `class` 关键字，**没有引入任何新的运行时机制**。它的产物就是第 2 步那套东西：

```js
class Dog {
  constructor(name) { this.name = name; }
  speak() { return "woof"; }
}
```

等价于：

```js
function Dog2(name) { this.name = name; }
Dog2.prototype.speak = function () { return "woof"; };
```

实测两者的产物：

```
typeof Dog              : function
两个原型都是普通对象    : object object
方法是不可枚举的        : []
但确实存在              : [ 'constructor', 'speak' ]
class 的方法默认不可枚举 : [ 'speak' ]
```

读这张输出：

- **`typeof Dog` 是 `"function"`** —— class 就是一个函数对象（第 01a 篇已经见过）。
- **`Dog.prototype` 是普通对象** —— 不是什么特殊的"类镜像"。
- **`Object.getOwnPropertyNames(Dog.prototype)` 是 `['constructor', 'speak']`** —— `speak` 确实挂在原型上。
- **`Object.keys(Dog.prototype)` 是 `[]`，但手写赋值的是 `['speak']`** —— 这是两者**唯一不等价**的地方：class 定义的方法默认不可枚举，直接赋值出来的属性是可枚举的。

> [!important] 所以「class 只是语法糖」这句话要精确理解
> 它指的是：**class 没有引入新的对象模型，只是把「函数 + prototype」这套写法包装得更好看**（并且顺手做了不可枚举、自动严格模式、必须用 `new` 调用这几件小事）。
> 底层还是那条原型链。**没有类镜像，没有类元数据。**

### 6. `new` 到底做了什么

`new Dog("旺财")` 只有三步：

1. 造一个新对象，把它的 `[[Prototype]]` 指向 `Dog.prototype`
2. 以这个新对象为 `this`，执行 `Dog` 函数
3. 如果函数返回了一个对象就用它，否则用第 1 步造的那个

手写一遍就彻底清楚了：

```js
function myNew(Ctor, ...args) {
  const obj = Object.create(Ctor.prototype);   // 1
  const ret = Ctor.apply(obj, args);           // 2
  return (ret !== null && typeof ret === "object") ? ret : obj;  // 3
}
```

实测它与 `new` 等价：

```
实例拿参数: 1 2
原型指向  : true
手写 new  : 3 4 true
```

**`new` 里面没有任何"类"的参与**——它只需要一个 `prototype` 属性。

### 7. 现在回头看 `instanceof`

第 01a 篇的结论在这里闭环了：

```js
d instanceof Dog
```

真实动作：从 `d` 开始沿 `[[Prototype]]` 往上走，看有没有碰到 `Dog.prototype`。

- "碰得到" → `true`
- 走到 `null` 还没碰到 → `false`

**它是链上的一次遍历，不是一次类型查询。** 这也解释了为什么 `interface` 不能用于 `instanceof`（第 01a 篇）：`interface` 只有类型层、没有值层，**它压根没有 `prototype` 这个属性可以拿来比对**。

## Python / Java 对照

| | JS | Python | Java |
|---|---|---|---|
| 链上挂的是什么 | **对象**（原型对象） | **类**（按 MRO 线性化） | 无链，编译期按类层次解析 |
| 实例属性在哪 | 对象自己 | `instance.__dict__` | 对象头 + 类元数据 |
| 方法在哪 | 原型对象上 | 类上 | 类的方法区 |
| 继承是 | 对象 → 对象 | 类 → 类 | 类 → 类（名义） |
| 运行时能改继承吗 | ✅ 能改 `[[Prototype]]` | ⚠️ 能改 `__class__`，但受限 | ❌ 不能 |
| 属性缺失时 | `undefined` | `AttributeError` | 编译期错误 |

> [!note] 三者最本质的差别
> - **Java**：方法是**类**的东西，编译期定死，对象只是数据。
> - **Python**：方法是**类**的东西，运行期沿 MRO 找，对象自己的数据在 `__dict__`。
> - **JS**：**没有类**。方法是**另一个对象**的属性，运行时沿链找。链可以随时改。

## 坑清单

> [!warning] 八条
> 1. **`class` 没有引入新的对象模型** —— 底层仍是原型链，"类镜像"之类的东西在 JS 里不存在。
> 2. **`typeof Dog` 是 `"function"`** —— class 就是一个函数值。
> 3. **class 的方法是原型上的属性，不是实例的** —— `dog.speak` 是共享的，`dog.name` 才是每实例一份。
> 4. **`"key" in obj` 会看原型链** —— 只想知道"自己有没有"用 `Object.hasOwn()`。
> 5. **`delete` 删的是自己的属性** —— 删完链上的同名属性会重新露出来。
> 6. **属性不存在返回 `undefined`，不报错** —— 拼错属性名不会炸，会静静地给你 `undefined`。（Python 会抛 `AttributeError`，Java 编译不过——JS 这里最不设防。）
> 7. **class 的方法不可枚举，手写 prototype 赋值的可枚举** —— 用 `for...in` 遍历时会看出差别。
> 8. **`prototype` 只在函数上有** —— 普通对象没有 `.prototype`，它有 `[[Prototype]]`（用 `Object.getPrototypeOf` 读写）。**这两个名字长得像，完全是两回事。**

---

## 回收钩子

- **原型链** → 第 5 节「`this` 绑定」：`this` 由**调用方式**决定，跟"方法挂在哪个对象上"没关系——这是原型链之后最反直觉的一步。
- **`class` 的两层身份**（值层 + 类型层）→ 卷二第 9 节「类与可见性修饰符」：TS 给 class 加的是**编译期**的修饰符（`private` / `readonly` / `abstract`），它们**不进入原型链**。
- **属性不存在是 `undefined` 而不是报错** → 卷二第 4 节「`null` / `undefined` 与 strict」：TS 最值钱的一条，就是把这类错误提前到编译期。
- **`interface` 没有 `prototype`** → 这解释了 TS 为什么用 `class` 而不是 `interface` 来做运行时继承。
