# 01a · 追问：类、反射，与「值 / 引用」到底该怎么理解

> 这是第 1 节《值与类型》的追问记录，回答两个问题。
> **本篇不依赖原文也能读。**

---

## 追问一：TS 的类型擦除，是不是导致 JS 没有 class、没有反射？

**不是。这里把两层东西混成一层了，这是本篇最重要的纠正。**

### 先看 Java 的模型（你的描述基本对，但有一处要修）

- **「万物皆对象」在 Java 里其实不成立。** `int` / `boolean` / `double` 这些原始类型都不是对象（`Integer` 才是）。Java 是**原始类型 + 引用类型**两个世界。这句口号是营销，不是事实。
- 你说的**「类的镜像」是对的**：每个被加载的类，在运行期都有一个 `java.lang.Class` 对象，里面挂着这个类的字段、方法、构造器元数据。
- **Java 的类型身份 = 类的身份**，元数据存在 `Class` 镜像里 → 所以**能反射类型**。

一句话：**Java 把「类型」做成了运行时的一等公民。**

### JS 的模型：没有类镜像，但**真的有 class**

JS 只有一种东西——**对象**（外加 7 种原始值）。它**没有** `Class` 那样的元数据对象。但——**`class` 在 JS 里是运行期真实存在的值，没有被擦除。**

实测（Node v25.7.0）：

```ts
class Animal { name = "generic"; speak() { return "..."; } }
class Dog extends Animal { speak() { return "woof"; } }

const d = new Dog();
console.log("typeof Animal        :", typeof Animal);
console.log("d instanceof Dog     :", d instanceof Dog);
console.log("d instanceof Animal  :", d instanceof Animal);
console.log("d.constructor.name   :", d.constructor.name);
```

真实输出：

```
typeof Animal        : function
d instanceof Dog     : true
d instanceof Animal  : true
d.constructor.name   : Dog
```

`typeof Animal` 是 `"function"`——**class 的产物就是一个普通函数对象**，外加一个挂在 `Animal.prototype` 上的对象。`new Dog()` 做的事只有两件：造一个新对象，把它的原型链指向 `Dog.prototype`。

### 所以你的四条说法，逐条判

| 你的说法 | 判定 | 修正 |
|---|---|---|
| JS 没有「类文件」 | ✅ 对 | 没有 Java 那种 `Animal.class` 字节码 / 类元数据 |
| JS 没有 `Class` 镜像 | ✅ 对 | 没有 `java.lang.Class` 的对应物 |
| JS 没有 class | ❌ **错** | `class` 是运行期的真实值，`instanceof` 能用 |
| JS 没有反射 | ⚠️ 不准确 | JS 有反射，但反射的是**对象和原型链**，不是静态类型 |

### 关键：`instanceof` 查的不是类型，是原型链

**JS 里根本没有「类型表」可查。**

`d instanceof Dog` 的真实动作是：从 `d` 出发，**沿着原型链往上走**，看有没有碰到 `Dog.prototype`。它是一次链上遍历，不是一次类型查询。

- `d instanceof Dog` → `true`（链上有 `Dog.prototype`）
- `d instanceof Animal` → `true`（链上更上面还有 `Animal.prototype`）

### 那被擦除的到底是什么？

**只有 TS 自己那层**：`type`、`interface`、以及所有类型标注。

```ts
interface Shape { w: number }
const s = {};
if (s instanceof Shape) { }   // 编译期就死
```

真实报错：

```
tp.ts(3,18): error TS2693: 'Shape' only refers to a type, but is being used as a value here.
```

硬绕过的话，运行期是 `Shape is not defined`——它从来就不存在。

### 钉死：一个名字可能同时属于两层

| 名字 | 属于哪层 | 运行期存在？ | `instanceof` 能用？ |
|---|---|---|---|
| `interface Shape {}` | 只有 TS 类型层 | ❌ | ❌ 编译期报错 |
| `type Alias = {}` | 只有 TS 类型层 | ❌ | ❌ |
| `class Animal {}` | **两层都有**：既是值也是类型 | ✅ 函数对象 | ✅ |
| `enum Color {}` | 两层都有（由 TS 生成） | ✅ 普通对象 | ✅ |

`class` 跨两层的含义：

- 作为**值**（JS 层）：能被 `new`、能进 `instanceof`
- 作为**类型**（TS 层）：能写 `const a: Animal`

`interface` 只有类型层、没有值层——所以它进不了 `instanceof`。**这就是 `class` 和 `interface` 最本质的区别，也是为什么 TS 选了 `class` 来做继承。**

> [!important] 三者的一句话总结
> - **Java**：类型身份存在 `Class` 镜像里 → 运行期可查 → **能反射类型**
> - **JS**：没有类型身份，只有**原型链** → 「查类型」= 走链 → 有对象反射，**没有类型反射**
> - **TS**：在 JS 之上加了一层**纯编译期**的类型 → 这层没有运行时对应物 → **无法反射**

### JS 到底有没有反射？

有，但它反射的是**对象和原型链**：`Object.keys` / `Object.getOwnPropertyNames` / `constructor.name` / `Reflect.*` / `Proxy`。

**TS 的类型**没有任何运行时对应物，所以「关于类型」的反射是彻底没有的。这两件事不要混。

> [!note] `enum` 是唯一的例外
> 它是 TS 里唯一会漏进运行时的类型，会生成一个真实的运行时对象。卷三第 5 节展开。

## 追问二：原始值是「句柄上直接就是值」，对象是「句柄 → 堆指针 → 数据」？

**分两半回答：作为「可观察行为」是对的；作为「内存布局」是错的，而且在 JS 里不可验证。**

### 对的那一半（这才是该记住的）

**赋值 / 传参时：原始值被复制，对象被共享。**

```js
let a = 1;
let b = a;
b = 2;
console.log(a, b);        // 1 2   —— b 是独立副本

let o1 = { n: 1 };
let o2 = o1;
o2.n = 2;
console.log(o1.n, o2.n);  // 2 2   —— 同一个对象

function mutate(x, obj) { x = 99; obj.n = 99; }
let p = 1, q = { n: 1 };
mutate(p, q);
console.log(p, q.n);      // 1 99

function reassign(obj) { obj = { n: 999 }; }   // 只改了函数内那个副本
let r = { n: 1 };
reassign(r);
console.log(r.n);         // 1
```

真实输出：

```
原始值 a/b       : 1 2 -> 互不影响
对象 o1.n/o2.n   : 2 2 -> 同一个对象
传参 p / q.n     : 1 99
函数内重新赋值 r.n: 1 -> 只改了本地那个指针
```

最后那个 `reassign` 的例子值得盯一下：**「函数内重新赋值不穿透」正是「传的是引用副本」的直接证据**。

**JS 传参永远是「传值」，只不过对象传的那个「值」是一个指向同一对象的引用副本。** 这与 Java 完全一致，Python 的「传对象引用」行为也相同。

### 错的那一半

「原始值在栈上直接存值，变量的槽里存一个指向堆的指针」——**这是 C / Java 的心智模型，JS 规范和引擎都不保证。**

- **规范完全不规定内存怎么摆。** ECMAScript 里没有「栈」、没有「堆」、没有「指针」、没有「句柄」。原始值是否内联、对象是否在堆上，纯属引擎实现细节。
- **连「对象都在堆上」都不是真的。** V8 会把小整数直接编码进指针（SMI），做指针压缩，逃逸分析还能把对象直接放到栈上。
- **JS 里无法观察地址。** 没有取地址运算符；`Object.is(a, b)` 只回答「是不是同一个对象」，不回答「在哪」。

所以这个模型在 JS 里**不可证伪**。不可证伪的模型不该拿来推理 bug——你会去猜「是不是指针复制错了」，而正确的问题永远是「**我是不是共享了同一个对象**」。

> [!warning] 一句话
> 别问「它在栈上还是堆上」，问「**我拿到的是副本还是同一个对象**」。
> 前者不可观测，后者决定一切。

### Python 人注意：三个语言根本不是同一个故事

| | 原始类型 | 变量是什么 | 「栈 / 堆」故事 |
|---|---|---|---|
| Java | 有（`int` 等，非对象） | 槽位 | JVM 实现细节，但语义稳定 |
| JS | 有（7 种） | 绑定 | 规范不规定 |
| Python | **没有**（连 `int` 都是堆对象） | 命名空间里的名字 | 完全不是这个模型 |

Python 里 `a = 1` 是把名字 `a` 绑到一个**堆上**的 `int` 对象；所以 `a is b` 对小整数会因缓存而为真。**别把三个语言的内存故事混着用。**
