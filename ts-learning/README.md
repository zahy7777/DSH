# TypeScript 心智模型课

> 概念先行，线性推进。每一节只引入**一个**新的心智概念；后面出现的每一样东西，都用已经建立的概念来解释，不提前消费还没讲的术语。

面向读者：熟 Python / Java，但没写过 JavaScript。

---

## 为什么是这个顺序

TypeScript 不是一门独立语言，它是「JavaScript 运行时 + 一层编译期类型」。这三个事实决定了学习顺序：

1. **TS 的语法地基有一半是 JS 语义。** 值怎么分类、`this` 怎么绑定、异步怎么调度、模块怎么加载——这些不是"JS 细节"，它们是 TS 语法的承载层。跳过它，类型标注就只能死记。
2. **TS 的类型在运行时全部消失。** 类型只存在于编译期。不理解这一条，后面所有"为什么这里查不出类型""为什么 `instanceof` 不管用"的困惑都无解。
3. **TS 的底层是两台机器：** tsc 的类型检查器（编译期），和 JS 引擎的事件循环（运行期）。"底层框架"要分头看，不能混成一团。

所以顺序是：**先立 JS 执行模型（语法地基）→ 再上 TS 类型系统（语法主体）→ 最后钻编译器与工程（底层）**。

## 四卷地图

### 卷一 · JS 执行模型（语法地基）

JS 的语法不只是"怎么写"，而是"这台机器怎么跑"。每个概念只依赖它前面的。

| # | 概念 | 一句话它解决什么 | 状态 |
|---|---|---|---|
| 1 | [值与类型](01-js-runtime/01-值与类型.md) | 世界里只有原始值和对象两种东西，其余全是变体 | ✅ |
| 1a | [值与类型·追问](01-js-runtime/01a-值与类型追问.md) | `class` 没被擦除、`instanceof` 走的是原型链；「值/引用」该按**行为**理解而不是内存布局 | ✅ |
| 2 | [变量绑定与作用域](01-js-runtime/02-变量绑定与作用域.md) | `let/const/var` 是三种**绑定规则**；`const` 锁绑定不锁对象；TDZ 是提升的另一种形态 | ✅ |
| 3 | [函数与闭包](01-js-runtime/03-函数与闭包.md) | 函数是一等值；闭包 = 函数 + 出生时的词法环境，且**捕获的是绑定不是值** | ✅ |
| 4 | [对象与原型链](01-js-runtime/04-对象与原型链.md) | 没有类，只有对象链；属性查找沿链走到 `null`；`class` 是语法糖 | ✅ |

| 6 | 单线程与事件循环 | 调用栈 / 任务队列 / 微任务——异步的一切根因 | ⬜ |
| 7 | Promise 与 async/await | 把回调地狱写成同步的样子 | ⬜ |
| 8 | 模块 | ESM 与 CJS 两套并存的加载机制 | ⬜ |

### 卷二 · TS 类型系统（语法主体）

到这里才真正开始写 TS。核心是第 2 节——它是 Java/Python 人最需要换掉的那个心智模型。

| # | 概念 | 一句话它解决什么 | 状态 |
|---|---|---|---|
| 1 | 类型标注与推断 | 什么时候必须写类型，什么时候让编译器自己算 | ⬜ |
| 2 | **结构化类型** ★ | TS 看"形状"不看"血统"——与 Java 名义类型彻底相反 | ⬜ |
| 3 | 联合 / 交叉类型与收窄 | "这个值可能是 A 也可能是 B"，以及怎么把它收窄成确定的 | ⬜ |
| 4 | `null` / `undefined` 与 strict | TS 最值钱的一条规定：默认不许为空 | ⬜ |
| 5 | 函数类型与重载 | 函数签名怎么描述、怎么表达"参数不同返回不同" | ⬜ |
| 6 | `interface` vs `type` 与工具类型 | `Pick`/`Omit`/`Partial`/`Record` 这类派生的本质 | ⬜ |
| 7 | 泛型 | 类型层面的参数化，以及 `extends` 约束 | ⬜ |
| 8 | 条件 / 映射类型与 `infer` | TS 的类型级编程——类型自己会计算 | ⬜ |
| 9 | 类与可见性修饰符 | TS 给 class 加了什么、`abstract`/`implements` 怎么用 | ⬜ |
| 10 | 声明文件 `.d.ts` | 怎么给没有类型的 JS 库补上类型 | ⬜ |

### 卷三 · TS 编译器内核（底层）

回答"类型检查到底是怎么做出来的"。读完你会有能力判断一条类型报错的**根因**，而不是试错式地加 `any`。

| # | 概念 | 一句话它解决什么 | 状态 |
|---|---|---|---|
| 1 | tsc 五段流水线 | scanner → parser → binder → checker → emitter | ⬜ |
| 2 | 符号表与类型表 | 编译器内部怎么表示"这个标识符指向什么" | ⬜ |
| 3 | 类型推导算法 | 上下文类型与候选推断，编译器怎么"猜" | ⬜ |
| 4 | 可赋值性判定 | 结构兼容 + 协变/逆变，为什么这里能赋那里不能 | ⬜ |
| 5 | 擦除的后果 | 为什么泛型不能 `instanceof`、为什么 `enum` 是例外 | ⬜ |
| 6 | 声明文件生成与声明合并 | `.d.ts` 是怎么被造出来的 | ⬜ |
| 7 | 模块解析 | 一行 `import` 具体去磁盘上找哪个文件 | ⬜ |
| 8 | 装饰器与元数据 | 唯一会往运行时塞东西的语法 | ⬜ |

## 每节文档的固定骨架

为了保证"概念线性"不被破坏，每节都必须按这个骨架写：

1. **心智锚点** —— 一句话，说清这节要装的到底是什么概念
2. **为什么需要它** —— 从上一节已建立的概念推出来，而不是凭空出现
3. **核心概念** —— 正文
4. **Python / Java 对照** —— 表格，三栏并排
5. **实测** —— 能直接拷去跑的代码 + **真实输出**（不是"应该输出"）
6. **坑清单** —— 与前两门语言不一致、最容易踩的点
7. **回收钩子** —— 明确写出这节的概念会被后面哪一节用到

## 关于代码

**这个仓库只放 Markdown，不产出 `.ts` 文件，不装依赖。** 代码全部写在文档的代码块里，直接读，不需要跑起来。

文档里贴的每一段输出和报错，都是本机真实跑过的结果（Node v25.7.0 / TypeScript 7.0.2），不是"应该输出"。想自己验一段的话：

```bash
node 例子.ts                              # 只擦类型，不检查
npx typescript@latest --noEmit 例子.ts    # 只检查，不产出
```

「只擦不查」和「只查不产」是两台不同的机器——这正是 **卷三 · TS 编译器内核**要讲清的事。
